## Production behaviour

### 1. Account statements: ingestion, matching, and the BAS-recon payout-update path

**Ingestion (XAS).** XAS is a standalone Go 1.24 microservice (Foundation gRPC :8080 / HTTP :8081 / internal :8082, MySQL via GORM, SQS + Kafka, Elasticsearch). Cron-triggered per-bank jobs (`internal/job/fetch_{axis,icici,idfc,yesbank}_statement/`, `fetch_statements_for_account/`) call bank-specific `IChannel` adapters (`internal/account_statements/fetch/channels/banks/{rbl,icici,axis,yesbank,idfc}/`) which build a `mozart.Request` and call `mozart.Service.MakeRequest()` (`internal/gateway/mozart/interfaces.go:10-12`) — i.e. **all bank calls go through Mozart**, not a direct bank API integration, and not a file drop. Parsed rows dedupe on `account_number+posted_date+type+bank_serial_number+amount+channel+bank_transaction_id` (`internal/account_statements/fetch/service/service.go:255-286`, per `08_downstream_admin.md` §2 claim 3, confirmed) and are batch-inserted into MySQL. CONFIRMED — `x-account-statements/AGENTS.md:1,44-48`; `.agents/skills/repo-skill/core/boundaries.md:39-50`.

**Statement → payout/FTA matching.** XAS owns matching, not the monolith and not PS directly. `internal/account_statements/enrich/service/service.go`:
- `EnrichWithStatement(ctx, statementID)` (`service.go:44-88`): fetches the statement, resolves its `account` (for `balance_id`), then calls `FetchEntityForEnrichment` with identifiers tried **in order UTR → GatewayRefNumber → CmsRefNumber** (`service.go:198-217`, constant list `service.go:198-201`) against `AccountStatementSourceEvents` rows (the payout/reversal events XAS ingested off SQS, `internal/source_events/`). If no match, the statement is marked `entity_type=external` (`service.go:79-81`, `markAsExternal` `service.go:328-343`). CONFIRMED.
- `EnrichWithSource(ctx, sourceEvent)` (`service.go:90-146`) is the mirror direction: a newly-arrived source event (payout/reversal) is matched against existing statement rows the same way. Defensive guards: `>2` matching statements for one UTR → no-op with an error report (`errcode.TooManyStmtsForUtr`, `service.go:120-127`); "dual debit or credit" (both matched rows same `Type`) → no-op (`isDualDebitOrCredit`, `service.go:132-138`, `343-350`).
- The actual field write is `internal/account_statements/enrich/service/enrichers/payout_enricher.go` — `PayoutEnricher.EnrichStatement`: sets `EntityType = "payout_reversal"` if the statement `Type==credit`, else `"payout"` (debit), and `EntityID = sourceEvent.EntityID` (the payout ID) (`payout_enricher.go:38-63`). **This write touches only XAS's own `account_statements` row (`entity_type`, `entity_id`) — it never sets a status field, and it is entirely local to XAS's DB.** CONFIRMED, matches `08_downstream_admin.md` §2 claims 2 & 4.
