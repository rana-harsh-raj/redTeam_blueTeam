## Source limitations preserved

**Shared Kafka is blocked by missing job registration.** Real FTS messages arrive, but Kafka bootstrap omits job.RegisterJobs(). Its process-local worker registry rejects the Shared Ledger enqueue before queue transport, leaving Payouts initiated while FTS is processed. No configuration-only repair was found. Fresh Direct Kafka skips Shared Ledger processing and reaches a signed terminal receipt while auxiliary dual-write still logs registration errors. The historical Direct-after-Shared timeout that this caused was previously inconclusive; Milestone 1 found and fixed the twin-side cause: `HandleFailedMessage`'s republish call dereferenced a nil Kafka producer (the twin's placeholder `[kafka_producer].Brokers` never resolved a compose service, and no `restart:` policy existed), so the consumer process panicked and stayed dead rather than restarting as production does. That is a **twin defect, now fixed (FD-001)**: `Brokers` points at `kafka:9092` and both consumers carry `restart: on-failure`. The underlying **source bootstrap gap is unchanged and remains recorded as expected failure EF-001** in `TWIN_SPEC/expected-failures.yaml`; Shared Kafka is not, and must not be, turned green. [Exact source/runtime evidence](KAFKA_ROUTE_EVIDENCE.md).

**Kafka metadata and failure/reversal handling are separate limitations.** Raw FTS source_account_id/bank_account_type do not populate the consumer's internal fts_fund_account_id/fts_account_type/fts_status DTO fields. The Shared enqueue failure occurs before the downstream Ledger operation could expose that mismatch's accounting consequence. Both consumers ignore FAILED/REVERSED. Direct success does not establish these branches; no translated message or core patch concealed them. FAILED and REVERSED delivered over Kafka have no fallback to payouts-service over Kafka: the consumer branch returns without applying any state change, the message is Acked and permanently dropped, and because FTS's status choice is exclusive, neither status reaches payouts-service over HTTP either unless the monolith's own Kafka consumer relays it for a monolith-created transfer (see EF-002/EF-003, and DEV-150 for the monolith-consumer asymmetry).

**Nonempty beneficiary type savings disagrees across repositories.** API permits the plural value, Payouts forwards it, and FTS accepts singular saving. The API-valid null baseline invokes Payouts' existing saving default. Passing that fixture does not validate nonempty savings. [Contract evidence](CONTRACT_FIXES.md).

**Recovery and webhook observations remain bounded.** The source's asynchronous payout.updated payload can observe a later entity state; ordered V21 stimuli do not repair that race. A bounded lost-callback test does not prove absence of every production repair mechanism. Manual FTS returned reconciliation is not automatic return detection or full XAS/BAS coverage. Preserve the Workflow expiry/self-approval gaps and Ledger application-level idempotency without claiming arbitrary concurrent exactly-once semantics. [Acceptance invariants](../../TWIN_SPEC/acceptance-invariants.yaml).

## Build, portability and transfer limits

All five candidate builds and module verification passed against available checked caches on Linux arm64. Cold-cache acquisition, amd64 and native-Linux acceptance remain unverified. [Build provenance](BUILD_PROVENANCE.md) records admitted source, generated RPC inputs, RX migration selection and patches. Configure machine-local paths through the admission-aware helper. [Migration readability](migration-readability-verification.json) verifies 118 admitted assets under UID 10001 in isolated containers; it is separate from physical-schema parity.

ARENA_DCS_URL changes endpoint selection; ARENA_STORK_JSON changes Twirp encoding. These explicit core transport/configuration patches can hide production endpoint-resolution and native Protobuf incompatibility. They are not business-state-machine repairs and remain fidelity limits. [Patch description](../../ENV2_COMPOSE/build/arena-patches/README.md).

The payouts image now stages `files/error/*.json` (bank error-code to public failure-reason/description maps), which were previously absent from the running container (`/app/files` did not exist), silently degrading every such mapping to the fallback with no visible failure (DEV-004, fixed in M1). Evidence: `.local/twin-repos/build-evidence-20260905T160213Z`; rebuilt payouts image `sha256:915299abaaf234dd7d8be73da9ec18c6b0554703184c6510c8516f3f6698838b`.
