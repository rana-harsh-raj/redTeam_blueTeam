## Changes made (file list)
New modules:
- `RED_LOOP/red_loop/hypotheses.py` — lifecycle state machine
  (`proposed→claimed→experiment_defined→executing→evidence_gathered→
  falsified|blocked|supported→replay_requested→reproduced|rejected→
  accepted|closed`, plus coordinator-only `deprioritized`), `Blocker` fixed enum,
  semantic `fingerprint` (normalized claim + target-assets), `duplicate_of`,
  priority (**int, higher first**), `highest_priority_open`, `rollup_by_state`
  (blocked counted separately from falsified), `validate_falsification`
  (falsified requires evidence_refs + executed experiment), `project_legacy`,
  and a durable `HypothesisManager` (`hypotheses_v2.jsonl`, dual-write + legacy
  adapter, duplicate-suppression event).
- `RED_LOOP/red_loop/leases.py` — `LeaseManager` (acquire/heartbeat/release,
  `reap_expired`, `reassign` with `handoffs.jsonl`, `recover_on_resume`),
  injectable clock, JSONL durable, restart-safe.
- `RED_LOOP/red_loop/experiments.py` — `CrossMerchantExperiment` with the six
  mandatory arms + `replay_required_if_unauthorized_effect`; `denied_at_layer ∈
  {broker,gateway,service,unknown}`; validators `can_support`/`can_falsify`/
  `can_accept` (merchant-B must execute with a state observation; denial never =
  safe; own-merchant success is control-only; accept needs independent replay).
- `RED_LOOP/red_loop/contexts.py` — 4 policies (`broad_coverage`,
  `deep_direct_accounting`, `identity_tenant_boundary`,

  (sequential, per-context budgets, machine-readable summary, exception-isolated);
  `MerchantDescriptor`.
- `RED_LOOP/red_loop/soak.py` — `Soak` unattended loop: per-cycle checkpoints,
  scenario rotation, dup suppression, stagnation detection, expired-lease
  reassignment, wall-clock + cycle budgets, `m4-direct-e2e-soak.json`,
  `no_productive_work` honest early-stop (no idle-loop).
- `RED_LOOP/red_loop/lifecycle_gate.py` — closing gate `lifecycle_gate(cid)`

## Unresolved questions
1. `surface/m3_1_acceptance.py` was intentionally **not** modified. Wiring the
   lifecycle gate into the *M3.1* overall pass/fail would flip M3.1 to NOT READY
   (its runs have a single legacy `proposed` hypothesis — exactly the hole the
   gate catches). The gate is exposed as an importable hook
   (`lifecycle_gate.lifecycle_gate(cid)`) + a `run.py lifecycle-gate` subcommand
   for the **M4** acceptance script to call. Confirm the M4 acceptance owner
   wires it (not me — acceptance ownership is separate).
2. Contexts/soak ship with an **injected runner** seam (fully unit-tested
   offline). A gateway-backed production runner that wires broker+judge+allowlist
   per policy is a thin adapter over the existing `run_campaign_cmd` setup; I did
   not add a `run.py contexts`/`soak` gateway command to avoid duplicating the
   provisioning block or risking `run_campaign_cmd`. See handoff step below.
3. Priority semantics follow the M4 mandate ("int; higher first") which
   **overrides** T08 §3.1's `min`-is-highest sketch. Highest = max priority, ties
   broken by earliest `created_at`.
4. Positive-path validation still needs the `calibration/tenant-isolation/`
   IDOR fixture (T08 risk #1): the live twin has no genuine cross-tenant bug, so
   the cross-merchant `accept` path can only be exercised against that fixture.

## Handoff instructions for the coordinator
1. **Wire contexts to fresh Direct merchants.** For each policy build a
   `contexts.MerchantDescriptor(merchant_id, key_id, namespace, label)` from a
   freshly provisioned Direct merchant (provisioner is owned by another stream —
   do not modify it) and pass `merchants={policy_name: descriptor}` to
   `ContextSupervisor.run(...)`. Inject a `runner(policy, merchant, budget,
   base_mandate)` that: reads `prompts/primary_mandate.txt`, appends
   `policy.mandate(base_mandate)`, builds a `Broker` for that merchant and a
   `Dispatcher(broker, store, judge_hook, hyp_manager=HypothesisManager(store),
   lease_manager=LeaseManager(store), allowed_tools=policy.tool_allowlist,
   owner=policy.name)`, then calls `run_campaign(...)` with a per-context
   `emergency_max_turns`/`max_wall_seconds`. Keep the reproducer a **different**
   provider family from the primary (decorrelation).
2. **Run a 2–8 h soak.** `Soak(store, cycle_runner=<gateway-backed cycle>,
   policies=contexts.POLICIES).run(wall_seconds=<2..8h in s>, max_cycles=<cap>,
   checkpoint_every=1, lease_ttl=300)`. The `cycle_runner` should run one bounded
   context turn-budget and return `{produced_work, new_hypotheses,
   duplicates_suppressed, experiments_executed}`. Output lands at
   `runs/<cid>/m4-direct-e2e-soak.json`. It stops honestly on
   `no_productive_work`/`stagnation`/`wall_clock_budget_exhausted`.
3. **Close-out.** Run `python3 RED_LOOP/run.py lifecycle-gate <cid>` (exit 1 =
   fail closed) and `lifecycle-export <cid>` before declaring a run successful.
4. **Re-verify models first** (`python3 RED_LOOP/run.py models`) — the M3.1
   snapshot is stale; the 4× context fan-out multiplies model spend and
   `claude-opus-5` is budget-capped/content-filtered.
5. **Docker recovery** (optional): set `M4_DOCKER_RECOVERY=1` to un-gate
   `service_restart`/`queue_consumer_restart`/`database_restart` — those are
   stubs raising until implemented against the live compose, since this stream
   could not touch docker.
