# T21 — World-Model Graph Export (Stretch H)

Milestone 4 Direct-reconciliation twin. Owner outputs only; repo otherwise read-only; no commit
(coordinator commits). Branch `milestone-4-direct-reconciliation`.

## What this is

A **source/spec-generated** typed graph of the M4 Direct twin. The generator
`RED_LOOP/surface/m4_world_model.py` PARSES committed artifacts and emits three views of one graph, so
re-running after a source change re-derives it (deterministic ordering → clean diffs). It is **not** a
hand-drawn diagram: every node/edge is derived from a parsed input, and every `real`/`executed` node or
`real` edge carries an evidence pointer (a committed artifact path or a `file:line` from the source map).

Outputs (owned):
- `reports/implementation/m4-world-model.json`  — canonical `{version, generated_at, generated_from[+sha256], nodes, edges, stats}`
- `reports/implementation/m4-world-model.graphml` — GraphML (PAYOUTS_SERVICE_GRAPH.graphml key/`<data>` conventions)
- `reports/implementation/m4-world-model.mmd`   — mermaid `flowchart LR`, grouped into 7 subgraphs, fidelity encoded via `classDef` (real=green, substitute=amber, fixture=grey, expected-failure=red, missing=purple/dashed)

## Generator design

Stdlib only (host python 3.14; no pyyaml assumed). One `build()` pass populates a `Graph` accumulator
(dedup on node id and `(src,dst,type)`), then three pure emitters + a validator.

Parsing strategy per input (chosen for robustness, since `_miniyaml` rejects several specs that carry
inline comments / colons):
- **docker-compose.yml** — regex sweep of top-level `services:` → 75 services classified into
  real-service / worker / substitute / datastore / migrate (migrations dropped).
- **route-matrix.yaml** — purpose-built tolerant block scanners: `direct_status_transports` (A–I inline
  flow-mappings, split respecting quotes/brackets), `direct_reconciliation_routes` (R1–R15 key/value
  children), `ingress_paths`. Each route's own `fidelity:` and `source:` fields become the node's
  fidelity + evidence — nothing invented.
- **source-map.md** — markdown-table scanners for §3 reservation state machine, §4 DA ledger event
  table (config rows + transactor-event list), plus the §5/§6 file:line citations used as edge evidence.
- **fidelity-matrix.csv** — `csv.DictReader`; `layer` column → clean fidelity (real_service/substitute/
  fixture), `fidelity_label` → coverage; `Route X` rows enrich the matching route node, the rest become
  `component` nodes carrying `production_reachability` + `deviation_ids`.
- **JSON** (`m4-route-coverage`, `m4-invariant-results`, `m4-direct-journeys`, `m4-direct-e2e-replay`) —
  `json.load`; drive route-coverage enrichment, the 6 executed G-gate invariants, journeys A–G, and the
  verified finding F-M4-001 (= replay candidate H-D3) + non-findings H-D4 / F-T10-1.
- **components.yaml / acceptance-invariants.yaml** — parsed with `_miniyaml` (both are well-formed);
  give the 24 architecture components and the 31 I01–I31 acceptance invariants.
- **init-queues.sh** — regex for SQS `create-queue` / SNS `create-topic`; only the M4 money-path queues
  are promoted to nodes.

Fidelity is normalised to the fixed vocabulary `real | substitute | fixture | expected-failure |
missing`; a separate `coverage` attr preserves the finer label (`executed | source_inferred |
implemented | independently_reproduced | deliberately_simplified | unresolved`). Determinism: nodes
sorted `(type,id)`, edges `(type,src,dst)`; `generated_at` pinnable via `M4_WM_GENERATED_AT` or
`SOURCE_DATE_EPOCH`.

## How to regenerate

```
python3 RED_LOOP/surface/m4_world_model.py
# deterministic re-run for diffing:
M4_WM_GENERATED_AT=2026-09-07T00:00:00Z python3 RED_LOOP/surface/m4_world_model.py
```
Prints node/edge counts by type and by fidelity, the three output paths, and a validation line. Exit 0
iff all validations pass; exit 1 lists problems. No docker / network / arena needed.

## Validation performed (all pass)

- JSON parses (round-trips through `json`).
- GraphML is well-formed XML — independently re-parsed with `xml.dom.minidom` (251 `<node>`, 151 `<edge>`).
- Mermaid lint: balanced `[]`, `subgraph`/`end` matched (7/7), all node ids `^[A-Za-z_]`, every edge
  endpoint is a defined node (0 dangling).
- Evidence rule: every `real`-fidelity or `executed`/`independently_reproduced`-coverage node, and every
  `real` edge, carries a non-empty evidence pointer (enforced in `validate()`; 0 violations).
- Determinism: two pinned runs produce byte-identical JSON.
- Cross-format consistency: JSON/GraphML both 251/151; 0 edges reference an undefined node.

## Inputs it could not fully parse

- `_miniyaml.load_file` raises on `architecture.yaml`, `route-matrix.yaml`, `runtime-topology.yaml`,
  `synthetic-data-model.yaml`, `expected-failures.yaml` (inline `#` comments and unquoted colons the
  subset parser rejects). Mitigation: route-matrix is parsed by the purpose-built block scanners above;
  expected-failures/architecture/runtime-topology content needed for nodes was taken from the structured
  siblings (source-map §4/§6, fidelity-matrix, init-queues) and a small curated EF id→title map derived
  from `grep`-verified titles in `expected-failures.yaml`. Only `components.yaml` and
  `acceptance-invariants.yaml` are consumed through `_miniyaml` (both parse cleanly).
- Runtime-topology (RDS/terraform versions) is "UNKNOWN — no terraform repo readable" in the spec itself;
  not modelled beyond the datastore nodes from compose.

## Unresolved / limitations

- Some `component` nodes (from the fidelity matrix, e.g. `payouts-api (PS core v1-candidate)`) conceptually
  overlap a compose `service` node of the same subject. Kept as a distinct **fidelity-ledger layer**
  (they carry `production_reachability` + `deviation_ids` the compose node does not); ids are namespaced
  so there is no collision, but a reader should treat `comp:*` as the audit view of the same subject.
- DA events not on the Direct money path (reward/fee/legacy variants) are typed `da_event` fidelity
  `missing` (present in ledger source, not exercised by the Direct twin) — this is why `missing`=18.
- The graph is scoped to the Direct/M4 journey; upstream prod services in the predecessor graph
  (dashboard, payout-links, vendor-payments, ValidX, etc.) are deliberately out of scope.

## Confidence

High on structure, counts, determinism, and the evidence-rule guarantee (all machine-checked). High on
the money-path / status-transport / reservation / DA-event / finding subgraphs (each node's fidelity and
evidence copied verbatim from a parsed artifact). Medium on the completeness of secondary edges — the
generator models the load-bearing relationships (ingress, status transports A–I, accounting chain
R5→R6→R7→R8→R12→ledger, statement ingestion R1→R3→R4, reservation transitions, invariant→journey
assertions, finding→route→symbol) but does not attempt an exhaustive call graph; adding an edge later is
a one-line change re-run against the same inputs.
