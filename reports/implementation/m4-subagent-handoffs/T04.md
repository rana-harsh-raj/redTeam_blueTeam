### 4. Reservations: model, creation, gate, transitions

**Store = Redis only, no table** (`reservation/store.go:1-16`). Keys (`store.go:227-241`): counter `"<prefix>:in_flight:{mid:balID}"` (INT, reserved total), items `"<prefix>:in_flight_items:{mid:balID}"` (HASH payoutID → `"<amount>:<dispatchedAtUnix>:<state>"`), tracked set `"<prefix>:in_flight_tracked_balances"` (members `mid:balID`), heartbeat `"<prefix>:in_flight_reconciliation_heartbeat"`. prefix `payouts`, TTL 6h, lag default 3m, max 2000 items, fail-open false (`config/default.toml:969-974`; twin `arena.toml:1040-1046` identical). States: `live`, `awaiting_balance_refresh` (`store.go:32-39`). "released"/"expired" are not states — an item is deleted on release, and the whole key pair expires by TTL (every Lua re-EXPIREs both keys).

**Gate selection:** `queueingstrategy.Select` (`strategy.go:46-49`): `reservationGate` iff `payout.MerchantConfig.IsFeatureEnabled(features.InFlightReservationEnabled)`, else `balanceBufferGate`. Called from `QueueIfLowBalance` only when `payout.GetQueueFlag()` is set (`fundAccountPayoutDirect.go:347-368`).

**Reserve** (`reservation_gate.go:170-305` → `store.Reserve` L249-275 → `reserveLuaScript` `scripts.go:41-75`): inputs gatewayBalance (x-balances), threshold (buffer), amount, payoutID, dispatchedAt=now. Decision table: threshold unresolved → `fail_closed`/queue without touching Redis (L207-211); store nil / heartbeat error / heartbeat missing / reserve error → `fail_closed`, queue unless `FailOpenOnRedisError` and buffer compare passes (L213-251); `atCapacity` (HLEN ≥ 2000) → `capacity_bypass`, buffer compare decides (L253-260); `!reservedOK` → `queued` (L262-264); reserved → dispatch with `Compensate` closure (L266-274). Lua admits iff `((gatewayBalance - counter) - amt) >= threshold` (`scripts.go:70`); same payout_id retry re-evaluates with self-exclusion and may release itself (L53-67). On success adds `mid:balID` to the tracked set (`store.go:266-273`). Log line `INFLIGHT_GATE_DECISION`.

**Compensate:** `Process` (`fundAccountPayoutDirect.go:127-197`) keeps `compensate` armed from the gate until the FTS handoff (`compensate = nil` at L197 after `OnEvent(created)` + `repo.Update`); on any error before that, `ReleaseReservationOnStore(..., "process_error")` runs (`reservation_hook.go:167-172`). Panic after reserve is a known gap (comment L137-139) → reconciler.

**Terminal hook:** `Payout.OnEvent` (`model.go:1398-1448`) calls `handleReservationOnTransition` (L1445) after every transition; hook (`reservation_hook.go:34-89`): only events processed/failed/reversed/cancelled/rejected (L42-48); skips non-Direct account types when hydrated (L57-59); requires `MerchantConfig` flag (L70-72; `fts_transfer_status_webhook.go:102-118` loads MerchantConfig for FTS-driven transitions precisely so this works); `processed` → `MarkAwaitingBalanceRefresh` (L83-86, `scripts.go:112-119`: state flip, counter untouched); others → `Release` (L88, `scripts.go:90-99`: HDEL + DECRBY, floor at 0 with `drift`).

### 8. Duplicate / out-of-order events and dedup

- **Reserve retry** (same payout_id re-driven by queued-payout worker or FTS handoff retry): Lua self-exclusion recheck keeps or drops the existing hold, never double-counts (`scripts.go:50-67`).
- **Duplicate terminal transitions**: `OnEvent` only fires on a valid state transition (`transition.Trigger`, `model.go:1405`; webhook path guards with `IsValidStateTransitionForTransferWebhook`, `fts_transfer_status_webhook.go:121`); hook releases are idempotent (§7 I-C) and `MarkAwaitingBalanceRefresh` returns 1 when already awaiting (`scripts.go:110-118`).
- **Balance-refresh event**: at-least-once from SQS; duplicates ⇒ NOOP; an *older* `balance_last_fetched_at` arriving after a newer one releases a subset already released ⇒ NOOP; malformed dropped, never retried (`job/x_balances_balance_refresh.go:110-119`); no message-id dedup exists or is needed. Concurrent consumers may double-observe the delay histogram (comment `reservation_hook.go:239-246`) — metrics only.
- **Reconciler vs live traffic**: F4 60 s grace preserves reservations taken after the DB snapshot (`scripts.go:175-184`); inverse race (release between snapshot and apply) re-creates a hold for ≤ 1 cadence, safe direction (`reconciler.go:45-50`).
- **x-balances fetch**: per-channel/request-type token bucket (`service.go:192-226`) suppresses bursts (returns cached amount, no DB write, no publish); dispatch dedup is by the `merchant_id NOT IN (top transacting ∪ blacklist)` exclusion (`server.go:205-217`) and ZSET score reset (`server.go:242-307`); no idempotency on the SQS job itself (MaxRetries 1, job swallows errors, `icici:99-129`).
- **Dual-write to monolith**: `XBalanceDualWrite` retries up to `MAX_ATTEMPTS_FOR_DUAL_WRITE` then deletes (`api/app/Jobs/XBalanceDualWrite.php:44-104`); `handleDualWrite` validates per item and updates by balance_id (`Details/Core.php:293-330`) — last write wins, no version check.
