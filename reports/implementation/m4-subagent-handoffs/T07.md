## 7. Namespace / isolation facilities

- **Campaign allocator** (`red_loop/allocator.py`): `NAMED = {M1 shared attacker, M2 direct victim, M3 workflow victim}` with secret file names; `allocate(attacker_key, victim_keys)` returns attacker (with secret, control-plane only) + victims (no secrets) + `actor_merchants`; `public_attacker_view` strips the secret. Isolation across campaigns = time window (`since_ts`) + per-campaign idempotency namespace `camp-<suffix>` + canary payouts (`provision_campaign`, `mint_victim_canaries`: unique `CANARY-…` strings in notes/narration, judge-only) + optional fresh funded attacker (`fund_fresh_attacker=True`).
- **Webhook sink**: one container; deliveries keyed by `merchant` from the URL path `/webhook/{merchant_id}`; query filter `?merchant=&payout_id=`; per-merchant HMAC secret loaded at boot from the stork seed (fallback `WEBHOOK_SECRET`). Scoping validated by `reports/implementation/sink-scoping-check.json`. stork-capture events filter by `owner_id`.
- **mozart-sim**: scenario rules keyed by `merchant_id` / attempt id / payout id → naturally per-tenant.
- **Faults**: scoped by exact merchant/transactor id across all stubs.
- **Per-run artifact dirs**: verifier `ARENA_RUN_DIR` (default `reports/implementation/runs/<UTC>-<pid>` or `<family>-<UTC>-<pid>`); campaigns `RED_LOOP/runs/<campaign_id>/{manifest.json, hypotheses/actions/observations/candidates/model_calls/events/responses/context_metrics.jsonl, evidence/}` (`state.CampaignStore`); clean boots `RED_LOOP/runs/cleanboot-<instance>/`.
- **Generated namespaces**: 32 seed namespaces (baseline, 26 verifier tests, 5 scenarios) each with its own M1/M2/M3 trio and own FTS source ids (`900000+ns*10+{1,2}`), so verifier tests never share a Direct source account.
- **Instance namespacing**: `ARENA_SUFFIX` on networks (`rzp-arena<suffix>`, `rzp-ingress<suffix>`) and named config/secret volumes; `COMPOSE_PROJECT_NAME` on containers/datastore volumes; only one arena fits in host RAM (L-001).
- **Shared across merchants (NOT namespaced)**: Kafka topics `rx-fts-status-update-events`, `rx-fts-status-update-retry-events` (consumer groups global); all LocalStack SQS queues (`seeds/localstack/init-queues.sh`: 36 queues incl. `stage-x-balances-balance-refresh-live`, `stage-x-balances-payouts-event`, `fts-async-processing`, `queued_payout`, `webhook_event`, …) and SNS topics `payout-updates-test-dev`, `journal-created`; FTS redis machinery queues (`default` + per-channel worker commands); Redis reservation store (`payouts:*` prefix, keyed by balance/merchant); the RBL pool source account 900001 (all Shared merchants) and the FTS `channel_information_status` rows; monolith-stub `/_arena/log` and mozart `/_arena/scenarios` events are global lists (filter client-side, as `compare-replays.py`/`trace_snapshot.py` do).
