# M4 Runbook — one-command entry points

All commands run from the repo root. Every target delegates to `scripts/m4.sh`,
which echoes what it does and calls the REAL project scripts. All are rerunnable.
Host Python is stdlib-only (3.14; no pytest/pyyaml/boto3) — runtime tests run
inside the `verifier` container.

## Targets

| Make target | scripts/m4.sh | What it does | Real script(s) |
|---|---|---|---|
| `make m4-boot` | `boot [<inst>|--live]` | Clean-boot a disposable arena instance (empty volumes, isolated networks); `--live` boots the in-place arena | `ENV2_COMPOSE/scripts/clean-boot.sh`, `up.sh` |
| `make m4-self-check` | `self-check [<campaign>]` | Provision N fresh Direct merchants + self-check + payout proof | `RED_LOOP/surface/m4_direct_provision.py all` |
| `make m4-test` | `test` | Verifier golden-run (26/0/0) + boundary suite + BAS + XAS/Ledger journeys | `golden-run.sh`, `verifier/m4_boundary.py`, `m4_bas_ingest.py`, `m4_xas_ledger.py` |
| `make m4-assurance-run` | `assurance-run` | 4-context gateway-backed autonomous run | `RED_LOOP/run.py contexts` |
| `make m4-replay` | `replay` | Clean-state, fresh-ID candidate replay (H-D3/H-D4/F-T10-1) | `RED_LOOP/surface/m4_replay.py` (owned by T19) |
| `make m4-acceptance` | `acceptance [--dry-run …]` | Evaluate all 74 gates → `m4-direct-e2e-acceptance.json` | `RED_LOOP/surface/m4_acceptance.py` |
| `make m4-evidence-verify` | `evidence-verify` | Build + verify the evidence manifest (G68/G69) | `RED_LOOP/surface/m4_evidence_manifest.py` |
| `make m4-clean` | `clean <inst>` | Safe teardown of a DISPOSABLE instance; refuses the live arena | `ENV2_COMPOSE/scripts/instance-cleanup.py` |

Pass extra args with `ARGS=...`, e.g. `make m4-acceptance ARGS=--dry-run`,
`make m4-self-check ARGS=m4-mycampaign`, `make m4-clean ARGS=m4-boot-XYZ`.

## Boot choice

`make m4-boot` defaults to a **disposable clean boot** (`clean-boot.sh <instance-id>`)
so it never disturbs the live arena. Use `make m4-boot ARGS=--live` to boot the
in-place arena via `up.sh`. Per D-003 (RAM: 11.65 GiB, one arena at a time),
clean-boot reverification is sequential: stop live → boot disposable → teardown →
restart live.

## Safety

- `make m4-clean` calls `instance-cleanup.py`, which **refuses the live default
  plan** (empty suffix / project `env2_compose`). It only removes a named
  disposable instance's Docker resources; host evidence dirs are never touched.
- No production/staging/internet. Containers stay on the `internal: true` network;
  model calls only via the host-side LiteLLM gateway (`RED_LOOP/llm.env`).

## Coordinator finalize order (Phase-8 acceptance)

Run after T17 (coverage/route/invariant artifacts) + soak + audit are in place:

1. `make m4-boot` (clean) then `make m4-self-check`, `make m4-test`,
   `make m4-assurance-run`, `make m4-replay` — regenerate the evidence set.
2. `make m4-acceptance ARGS="--tested-commit <SHA>"` — evaluate 74 gates against
   the code under test. `evidence_commit` is null on this pass.
3. `make m4-evidence-verify` — build + verify the manifest binding all evidence.
4. Commit the acceptance JSON + manifest as a **separate evidence commit** (the
   coordinator commits; agents do not). The acceptance JSON records
   `tested_commit` and must never claim it existed inside that commit.
5. Create the annotated tag `red-loop-m4` on the evidence commit (closes G73).
6. Re-run `make m4-acceptance ARGS="--tested-commit <SHA> --evidence-commit <SHA>"`
   to stamp the evidence commit, then `make m4-evidence-verify` once more as the
   authoritative G68/G69 recompute.

The self-referential hash is handled by construction: the manifest is always
built **last**, and the acceptance evaluator's inline G68 excludes the
acceptance JSON from its recompute (that file is regenerated by the very run);
`make m4-evidence-verify`, run after the commit when nothing regenerates the
acceptance JSON, is the authoritative check that includes it.
