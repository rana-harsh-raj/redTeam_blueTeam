## First final capture and review

The [14:06 first capture](audits/final-current-boot/audit-summary.json) correctly retained a blocked result. Review found an audit reader defect: the Mozart directory is intentionally owned by UID 10001 with mode 0500. A root helper with all capabilities dropped could not enumerate it, and the original recursive reader returned an empty inventory. The corrected reader uses UID 10001 and explicitly fails on unreadable directory enumeration. The subsequent byte comparison passed without changing the volume, permissions or generation inputs.

The Redis hostname match was the public `github.com/jemalloc/jemalloc/issues/1328` memory-overcommit help link. Two MongoDB `dochub.mongodb.org/core/…` links came from startup warnings. The classification requires the observed host/path and corresponding service/startup context; another hostname on the same line remains unresolved. This classification concerns log text, not evidence of outbound traffic.

The Redis credential-shaped matches were 36-character task UUIDs. Source evidence is FTS's pinned `github.com/RichardKnop/machinery v1.9.1`: `v1/tasks/state.go:21` defines `TaskUUID`, `TaskName`, `State`, `Results`, `Error` and `CreatedAt`; `v1/backends/redis/redis.go:319–326` persists that state at the task UUID key; `v1/server.go:170` generates the UUID. The reader retains raw findings, verifies this relationship, redacts only proven identifier values and reruns the scanner. A UUID shape alone does not establish this classification. The [logical store report](audits/final-current-boot-reviewed/logical-store-secret-scan.json) preserves both scans and proof counts.

## Issuer correction

Kong's earlier default was a production hostname. `_mint_passport_jwt` places the issuer in a signed identity claim, and Payouts logs include that claim. The inspected verification path does not dereference it as a URL. Kong's source default and explicit Compose environment now use `https://identity.arena.invalid`; the reviewed final capture verifies that running override. This intentionally changes issuer identity while preserving the configured key identifier, generated signing key, RS256 algorithm and validity timestamps.

Pinned verification evidence is Payouts `pkg/passport/handler.go:63–79`, Passport SDK `github.com/razorpay/goutils/passport/v3@v3.4.0/handler.go:52–80` and `passport.go:27`, and effective `github.com/golang-jwt/jwt@v3.2.2+incompatible/claims.go:32–59` standard time validation. The original finding is preserved in [the pre-replay1 report](SECRET_AND_ENDPOINT_AUDIT_PRE_REPLAY1.md). Functional acceptance and DNS/egress evidence belong to their separate reports.

## Interpretation and remaining limits

Explicit arena fixture credentials trace to checked-in templates. Splitz identifiers, request hashes, UUID idempotency keys and inherited public GPG fingerprints have field/type evidence. MongoDB SCRAM values have cryptographic generated-origin evidence; LocalStack's test key has certificate/public-key evidence. Binary findings require exact source constants and immutable-file hashes. Fresh-input consistency supports arena origin but does not externally attest historical randomness.

Remaining limits are rotated-away, earlier and future logs; protected MongoDB session metadata; Redis databases outside configured DB0; in-memory SQS payloads; datastore/substitute image root filesystems; and nonprintable, encrypted or compressed secret encodings. Logical snapshots and decoded Kafka payloads do not establish that every database/index page is free of deleted or hidden data; concurrent Kafka rotation limits snapshot consistency. Public bank metadata, service source and dependencies intentionally remain real reference inputs. Synthetic applies to arena customer fixtures and local credentials.

## Reproduction

The reusable [audit package](../../ENV2_COMPOSE/preflight/audits/README.md) validates checkout ownership, refuses to overwrite an existing capture, and checks running service identities before and after its readers. Run from the workspace root with a fresh output directory:

```sh
ARENA_ROUTE_PROFILE=monolith python3 ENV2_COMPOSE/preflight/audits/audit.py \
  --build-evidence .local/twin-repos/build-evidence-20260905T113414Z \
  --output reports/implementation/audits/new-current-boot \
  --read-unused-mozart
```

Six offline boundary tests pass after the reader changes:

```sh
python3 -m unittest discover -s ENV2_COMPOSE/preflight/audits -p 'test_*.py' -v
```

These cover workspace isolation, missing scanner reports, preserving novel candidates during known-value and task-ID classification, requiring the persisted task-key relationship, and narrowly classifying diagnostic URLs.
