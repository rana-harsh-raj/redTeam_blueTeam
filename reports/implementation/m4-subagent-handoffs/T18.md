## Self-referential hash protocol (Phase 8)

- The acceptance JSON records `tested_commit` (code under test) and
  `evidence_commit` (the SEPARATE commit that carries the acceptance JSON +
  manifest; **null on the first pass**). The artifact carries an explicit
  `self_reference_note` and never claims it existed inside `tested_commit`.
- The manifest is always built **last**. The evaluator's inline G68 recompute
  **excludes** `m4-direct-e2e-acceptance.json` (that file is regenerated by the
  very run, so a prior manifest's hash of it is legitimately stale). The
  authoritative G68/G69 check is `make m4-evidence-verify`, run after the evidence
  commit when nothing regenerates the acceptance JSON — it recomputes every
  artifact including the acceptance JSON, self_sha256, and companion checksum.
- Baseline commit checks resolve by SHA + git object type (`red-loop-m3.1` tag →
  `3a044f8`; `twin-v1.0` → `78def24…`; `milestone-2-red-loop` → `a107612…`),
  **branch-independent** — this avoids the M3.1 C-002 evaluator-scope bug.

5. Create annotated tag `red-loop-m4` on the evidence commit (closes G73).
6. `make m4-acceptance ARGS="--tested-commit <SHA> --evidence-commit <SHA>"`, then
   `make m4-evidence-verify` again (authoritative G68/G69).
