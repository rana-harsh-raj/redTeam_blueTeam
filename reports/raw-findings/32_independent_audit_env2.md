## 1. Claims vs evidence

(healthy)`, matching the compose service list (`docker compose --profile datastores --profile migrations --profile substitutes --profile core --profile verify config --services` returns 67 services, validates cleanly, exit 0). One exception worth a footnote: `ledger-scheduler` shows `Exited (0)` — consistent with the doc's own "one-shot" framing (`ENV2_BUILD_RUNBOOK.md:131`), not a contradiction. `ledger-api` showed only "Up 9 minutes" against ~1-2h for its neighbors at inspection time — the doc doesn't mention any ledger-api restart, a minor unexplained gap but not a false claim.

**"8 passed, 6 failed, 12 skipped"** (`ENV2_BUILD_STATUS.md:50`) — **supported**. `raw-findings/env2-logs/verifier-run28.log` tail: `6 failed, 8 passed, 12 skipped, 2 warnings in 138.40s`, `exit=1`. Per-verifier PASS/FAIL rows in the status table match the log's individual test names.

**"Isolation evidence for the same window: EGRESS_AUDIT.md PASS"** (`ENV2_BUILD_STATUS.md:68`) — **not substantiated as stated**. `EGRESS_AUDIT.md:1` timestamps the capture `2026-09-04T17:36:27Z`, duration **60s** (ends ~17:37:27Z). The status doc says the final verifier run completed "~17:45 UTC" — an ~8-minute gap, and the verifier itself took 138s to run. `scripts/golden-run.sh:31` invokes `network/egress-audit.sh 120` (120s) when run via `--with-egress-audit`, but the artifact on disk records a 60s duration — the value used by the standalone manual invocation documented in `ENV2_BUILD_RUNBOOK.md:70` (`bash network/egress-audit.sh 60`), not the `golden-run.sh --with-egress-audit` path the status doc cites as the golden-run command (`ENV2_BUILD_STATUS.md:48`). Most likely explanation: `EGRESS_AUDIT.md` was generated by a different (earlier) invocation than run 28, then presented as covering "the same window." The underlying network isolation claim (`internal: true`, verified in `docker-compose.yml:79-91`) is independently credible, but the specific evidentiary link between this exact `EGRESS_AUDIT.md` and this exact golden run is not established by the files as given.

**"zero error lines in a 40s steady-state scan"** (`ENV2_BUILD_STATUS.md:5`) — no corresponding log/artifact was found under `raw-findings/` or `ENV2_COMPOSE/` (only `up-clean.log` and `verifier-run28.log` exist in `env2-logs/`). Unverifiable from the package as delivered — **claim not backed by an attached artifact**.

**W9/W10 schema and worker-model corrections** (`ARCHITECTURE_DELTA.md:82-90`) — **supported**, and honestly self-flagged: `raw-findings/31_env2_bringup_notes.md:82-83` explicitly states "the migration-count rows in ENV2_BUILD_STATUS therefore mean 'migrations apply', not 'schema equals production'" and "same class of drift is likely elsewhere ... only the first blocker is patched." This is a rare case of a claim being *more* honest than a naive reading of the headline table would suggest — good practice, noted positively.

## 2. Safety gate

Network/host controls are real and verified in `docker-compose.yml`: `rzp-arena` is `internal: true` (:79-85), only `kong-lite`+`verifier` dual-home onto `rzp-ingress` (:9-10 comment, cross-checked against service definitions), `x-runtime-security` applies `read_only: true` + `no-new-privileges` (:41-51) to the 5 real services, `x-proxy-env` blackholes `HTTP_PROXY/HTTPS_PROXY` to the discard port `127.0.0.1:9` with an explicit **allow-list** `NO_PROXY` (:65-76) rather than a blocklist. `secrets/*.txt` are `0600` (`ls -la secrets/`), never baked into images (`.gitignore:6-9` excludes `secrets/`, `generated/`), and the compose file's own header (`docker-compose.yml:1-18`) states the no-host-mount invariant, which a scan of the file confirms (no `~/.docker`, no `/var/run/docker.sock`, no host path other than `./generated`/`./secrets`/`./seeds`/`./verifier`).

Exceptions found, each rated:

- **LocalStack ARN exemption** (`preflight/preflight.py:44`, `config/generate.py:267`) — `arn:aws:...:000000000000:...` is the only ARN pattern excused from the `arn:aws` refusal; both the gate and the sanitizer independently hardcode the same synthetic account. **Acceptable** — narrowly scoped, matches LocalStack's own fixed test-account convention, symmetric in both enforcement points.
- **`kong-lite` `/_arena/mint`** (`substitutes/kong-lite/server.py:205`, `CONTRACT.md`) — refuses any merchant id not prefixed `ARENA`. **Acceptable** — cannot mint a passport for anything resembling a real merchant.
- **Preflight's hostname inventory is silently capped at 200 rows** (`preflight/preflight.py:256`: `for host, source in endpoints[:200]`) with no "N more, truncated" marker in the generated `SAFETY_PREFLIGHT.md`. The actual **gate** (the four `FORBIDDEN_PATTERNS` regexes) runs over the unbounded scan and is not weakened by this — but the file's own stated purpose ("investigate before running `scripts/up.sh`" if anything here looks like a real host, `SAFETY_PREFLIGHT.md:41-43`) is undermined: both the `reports/` and `ENV2_COMPOSE/` copies of `SAFETY_PREFLIGHT.md` are byte-identical and cut off mid-alphabet at `build-host.sh` (line 246 of 247), meaning a human reviewer manually scanning for "does anything here look like a real host" never sees entries starting with c–z. **Needs attention** (silent truncation of a document whose whole job is manual eyeballing).
- **An unsanitized third-party domain survives in a base config layer**: `generated/fts/env.default.toml:603-679` (and its source template `config/templates/base/fts/env.default.toml:603` — copied verbatim, "sanitize"-mode per `config/generate.py:122`) hardcodes `URL = "htTPS://test124.free.beeceptor.com/"` (a real, live, third-party webhook-capture SaaS) across 8 `[webhook.*]` sections. `sanitize_forbidden()` (`config/generate.py:281-295`) only rewrites `razorpay.*`/`amazonaws.com`/`arn:aws`/`169.254.*` — it has no general third-party-domain rule, so this string passes through untouched. It is fully overridden in `generated/fts/env.arena.toml:161-205` (7 of the 8 sections point to the blackhole `http://127.0.0.1:9/mock/webhook`, the 8th — `webhook.payout` — to `monolith-stub:8080`, both confirmed present), and `fts-web` is invoked with `-env=arena` (`docker-compose.yml:983`), so the override should apply at runtime. Verified this is the *only* live external domain surviving sanitization (case-insensitive `http(s)://` scan across all of `generated/`, cross-checked against `SAFETY_PREFLIGHT.md`'s own hostname table where `beeceptor.com` does appear, line ~230). **Needs attention** — the sanitizer's safety net does not generalize beyond Razorpay/AWS hosts, so it currently depends entirely on override-completeness in `arena.toml` rather than defense-in-depth; the `internal: true` network + proxy blackhole would still catch a failed override, so residual risk is low, but this is exactly the kind of gap the preflight hostname table exists to catch — and (per the point above) a domain further down the alphabet could scroll off before a reviewer sees it.
- **`generated/<svc>/*.toml` are `0644`** on the host filesystem (`ls -la generated/payouts generated/fts`), versus `secrets/*.txt` at `0600`, despite `SAFETY_PREFLIGHT.md:28` itself naming `generated/<svc>/*.toml` as a credential source ("credentials inlined by config/generate.py from secrets/*.txt"). They are bind-mounted read-only into containers and gitignored, so this isn't a container-escape or repo-leak vector, but it is weaker host-side file hygiene than the secrets directory receives for what the package's own inventory calls equivalent material. **Needs attention** (cheap fix: `umask`/`chmod 0600` in `config/generate.py`'s file-write step).
- **The two confirmed real-egress SDK bugs** (`goutils/dcs` ignoring `Mock=true`, plain `sqs` driver ignoring `Endpoint`) are documented with real captured evidence from the pre-mitigation host spike (`ENV2_BUILD_STATUS.md:38-39`, `EFFECTIVE_CONFIG_GAPS.md:479-481`) and mitigated three ways each (network-level `internal: true`, proxy blackhole, and a source patch). **Acceptable** as mitigated, but see §4 — the DCS source patch itself is not reproducible from this package.

## 3. Fidelity risks

- **Mozart substitute is not the one the architecture pass recommended.** `ARCHITECTURE_DELTA.md:167` and `EFFECTIVE_CONFIG_GAPS.md:311` both conclude `mozart -mock` (the real binary's built-in mock mode, byte-identical prod routing/config/error-code pipeline) is "preferred over building a new synthetic simulator from scratch." `ENV2_BUILD_STATUS.md:15` records it "still unbuildable (private deps)"; the arena instead runs `mozart-sim`, a hand-built Python substitute, and the verifier is configured to treat it as the live-bank-path signal (`raw-findings/31...md:109`, `VERIFIER_SPEC.md:685`). `VERIFIER_SPEC.md:222-229` explicitly ties its top confidence tier (`END_TO_END_CONFIRMED` vs. capped `CODE_CANDIDATE`) to whether the *real* `mozart-mock` path was used — a rule written before `mozart-sim` existed and never revisited for it. `ENV2_BUILD_STATUS.md:50`'s headline "the end-to-end payout path is proven" therefore rests on a lower-fidelity substitute than the one the project's own prior analysis said to use, without flagging the substitution in the headline claim (it is disclosed, accurately, only in the fine print of two other documents).
- **`monolith-stub` does not reproduce the one concrete, currently-live production failure the audit itself surfaced.** `ARCHITECTURE_DELTA.md:5,59` (the W4/C42 correction) is explicit: "any environment substitute of the monolith must model both" — implement the dual-write handler *and* have it fail the way `ApprovedPayoutProcessor` fails today (`Table 'api.payouts' doesn't exist`), or explicitly choose not to. `substitutes/monolith-stub/server.py:170-176,468` implements `/payouts_service/dual_write` as an unconditional 200 sink (`{"status":"queued"}`). No flag or mode exists to reproduce the documented outage. This is a silent, undocumented divergence from the audit's own stated requirement for this exact component.
- **Credential topology is flatter than production.** `raw-findings/31...md:48-59` — every callee's inbound auth section was bound to the *same* generated secret as its one caller, because that's the only pairing the arena needed to boot. This is reasonable for Env 2's scope but means credential-rotation, wrong-secret, and multi-tenant-auth-boundary scenarios are structurally untestable here — worth stating explicitly rather than leaving implicit.
- **Failed verifiers are, on inspection, real fidelity findings, not test bugs** — and are reported as such, which is good: V12 (`ENV2_BUILD_STATUS.md:63`) flags an open question about whether the DCS-stub reservation key/value shape actually matches production; V24's queued-dequeue failure (`:64`) traces to the arena lacking the monolith's journal-created balance-sync consumer (confirmed absent in `raw-findings/31...md:105`); V04's failure is attributed to the real, catalog-known weak invariant (`VERIFIER_SPEC.md:158-159`, no DB unique index) rather than tooling. These are legitimate, well-evidenced findings about the *target system*, correctly not laundered into "arena bug" framing.
- **`ARENA_WAIT_SCALE=6×`** (`raw-findings/31...md:100`, `VERIFIER_SPEC.md:684`) masks whatever timing-dependent bugs a 1× production window would expose (e.g., real race conditions the V06 failure hints at — `ENV2_BUILD_STATUS.md:62` describes payouts reaching `processed` "in seconds," faster than the verifier's synthetic wait pattern expects). Any timing-sensitive invariant is being tested against arena-scaled timing, not production timing, by design — reasonable for now but should be called out as a stated limitation, not left implicit in a script default.
- **FastCron cadence is invented** (`ENV2_COMPOSE`'s `cron-driver`, per `EFFECTIVE_CONFIG_GAPS.md:81`: "arbitrary fixed interval... without matching prod cadence") — acceptable per the project's own risk framing (idempotent sweep jobs, not the primary path) but should stay flagged wherever golden-run results are quoted, since `payouts_auto_cancel_on_expiry`/stuck-payout-dispatch timing-dependent scenarios are exactly what this arena might later be asked to reproduce.

## 4. Reproducibility

`bash scripts/up.sh` (`ENV2_COMPOSE/scripts/up.sh:1-152`) is a clean, well-ordered, idempotent script (secrets → config → preflight hard-gate → datastores → migrations+schema-patch → seeds → substitutes → core → health wait) and would work **once the five runtime images already exist**. It does not build them. Reaching that state requires the separate BUILD phase (`ENV2_BUILD_RUNBOOK.md:22-42`), which is **not fully reproducible from this package**:

- `build/build-host.sh:79-115` expects `$REPOS_ROOT/{payouts,ledger,fts,cfa,x-balances}` to already be the **patched copies** — with the payouts `go.sum` ifsc-hash re-recording and the 3-line `ARENA_DCS_URL` wrapper applied, plus a `replace github.com/razorpay/goutils/dcs => .../arena-patches/goutils-dcs-<ver>` in three `go.mod` files. No script, diff, or patch file anywhere under `ENV2_COMPOSE/` performs this. `grep -rn "arena-patches" ENV2_COMPOSE/` returns zero hits; the only occurrences of `arena-patches`/`env2-spike` in the whole tree are prose mentions in `reports/` pointing at `$SPIKE/env2-spike/...` — a scratch directory from an earlier spike session that is not part of this package and whose `$SPIKE` root is never resolved to a concrete path anywhere in the delivered docs. A new engineer following the runbook verbatim has no way to reconstruct the `arena-patches/goutils-dcs-*` module replacement (the actual fix for the one confirmed real-egress SDK bug) without re-deriving it from the prose description in `ENV2_BUILD_RUNBOOK.md:34-35` from scratch.
- The runbook's own §0 prerequisites (`ENV2_BUILD_RUNBOOK.md:9`) require `gh auth setup-git` and working `GOPRIVATE` access to `github.com/razorpay/*` — a credential dependency outside the package's control, undocumented as to which specific scopes/teams are needed.
- `SAFETY_PREFLIGHT.md`/`EGRESS_AUDIT.md` are regenerated by every run (`preflight/preflight.py:3-4`, `network/egress-audit.sh:94`) and are also in `.gitignore` (`.gitignore:8-9`) — meaning the two safety artifacts a reviewer is told to trust are, by design, not the same bytes a fresh clone would ever see; the copies audited here are this run's output, not a committed baseline. Reasonable given their per-arena secret content, but worth stating plainly in the runbook (it currently is not).
- Given a working `REPOS_ROOT` and images, `bash scripts/up.sh` then `bash scripts/golden-run.sh --with-egress-audit` is genuinely mechanical and matches what `docker ps` shows running. The gap is entirely in the BUILD phase's dependency on an out-of-package scratch artifact, not in the compose/runtime layer.

## 5. Top 10 fixes, by risk

1. **Bring the `arena-patches/goutils-dcs-*` module-replacement source into `ENV2_COMPOSE/` proper** (e.g. `build/arena-patches/`) with a script that applies it to a fresh clone — this is the actual fix for the one confirmed real-egress SDK bug and currently lives outside the auditable package.
2. **Automate the BUILD-phase repo-copy patches** (go.sum re-record, 3-line DCS wrapper, go.mod replace) as a script, not prose — today reproducibility depends on a human re-reading `ENV2_BUILD_RUNBOOK.md:33-37` and re-deriving the exact edits.
3. **Give `monolith-stub` a mode that reproduces the W4/C42 dual-write failure** the audit's own prior pass flagged as required — currently the stub always succeeds, silently diverging from a documented instruction.
4. **Remove the 200-row silent cap on `SAFETY_PREFLIGHT.md`'s hostname table**, or explicitly print "N more truncated" — a document whose stated job is manual eyeballing for anything that "looks like a real host" currently hides most of its own data with no indication it's incomplete.
5. **Extend `sanitize_forbidden()`/preflight beyond Razorpay/AWS patterns** to catch arbitrary third-party domains in vendored default configs (the `beeceptor.com` case) — currently caught only by manual `arena.toml` override discipline plus network-level defense-in-depth, not by the sanitizer itself.
6. **Re-run (or re-timestamp) the egress audit concurrently with the exact golden run being cited** — the current `EGRESS_AUDIT.md` (60s, ends ~17:37Z) does not obviously overlap the "~17:45 UTC" final verifier run it's presented alongside.
7. **`chmod 0600` (or tighter) the `generated/<svc>/*.toml` files** — they carry the same class of material as `secrets/*.txt` but ship at `0644`.
8. **Fix the schema-drift class systematically**, not one column at a time — `beneficiary_bank_code` was found because it happened to block the golden path first; `raw-findings/31...md:83` already predicts more exist. A diff of every table's live prod DDL vs. `goose`-applied schema (even schema-only, per `EFFECTIVE_CONFIG_GAPS.md:203-207`'s already-requested export) would close this class instead of patching symptoms.
9. **Decide and document mozart-sim's actual confidence tier** — either update `VERIFIER_SPEC.md`'s `END_TO_END_CONFIRMED` rule to explicitly cover it, or stop describing golden-run results as "proven end-to-end" without qualifying that the officially-preferred `mozart -mock` substitute is not the one running.
10. **State `ARENA_WAIT_SCALE=6×` and the FastCron-cadence approximation as explicit, standing caveats** wherever golden-run pass/fail numbers are quoted (not just in script comments) — both materially affect whether a timing-sensitive failure would even be observable.
