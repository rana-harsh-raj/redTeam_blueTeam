## Changes made (file list) — all additive, nothing in the DO-NOT-TOUCH set edited

  adapter. `make_runner(store, judge_hook_factory=..., primary_model=..., ...)`
  returns `runner(policy, merchant, budget, base_mandate)` that: provisions +
  self-checks ONE fresh Direct merchant per policy (`provision_direct_merchant`

  `reports/implementation/m4-lifecycle-validation.json`. Has its own CLI
  (`contexts` / `soak` / `validate-lifecycle` modes).
- `RED_LOOP/run.py` — additive `contexts` and `soak` subcommands (delegate to the

  (`campaign`/`models`/`preflight`/`lifecycle-gate`/`lifecycle-export`/`resume`/
  `recovery-matrix`) untouched.

### The one integration subtlety (no frozen file edited)
`run_campaign` constructs `Dispatcher(broker, store, judge_hook)` internally, so
the policy tool allow-list + `HypothesisManager`/`LeaseManager` + `owner` cannot
be passed through its signature. Rather than edit the frozen `campaign.py`,
`context_runner` rebinds the `campaign.Dispatcher` module attribute to a
`functools.partial` carrying those args for the duration of the call and restores
it in a `finally`. ContextSupervisor/Soak run contexts sequentially, so the
rebind is race-free. This kept `campaign.py`, `tools.py`, `provisioner_direct.py`
etc. byte-for-byte unchanged — no coordinator hook was required.

## Instructions for the coordinator — launching a 2–8 h soak
1. `source RED_LOOP/llm.env` (never echo `LITELLM_API_KEY`).
2. Re-verify models: `python3 RED_LOOP/run.py models`. If `claude-opus-5` is still
   429, keep `--primary-model kimi-k3` (reproducer stays gpt-5.5, different family).
3. Long soak: `python3 RED_LOOP/run.py soak --primary-model kimi-k3
   --wall-seconds <7200..28800> --max-cycles <cap> --checkpoint-every 1
   --lease-ttl 300`. It provisions a fresh Direct merchant per policy lazily
   (cached across cycles), rotates the 4 policies + 4 scenarios, checkpoints the
   manifest each cycle, and stops honestly on
   `no_productive_work`/`stagnation`/`wall_clock_budget_exhausted`. Output:
   `RED_LOOP/runs/<cid>/m4-direct-e2e-soak.json`.
4. Resume after a kill: `python3 RED_LOOP/run.py soak --resume <cid>` — the soak
   reaps/reassigns stranded leases on entry and continues from the manifest
   checkpoint.
5. Close out: `python3 RED_LOOP/run.py lifecycle-gate <cid>` (exit 1 = fail
   closed) and `lifecycle-export <cid>`, then the arena-wide egress audit.
- The 4× context fan-out multiplies model spend; kimi-k3 is economical but budget
  the run. If the gateway budget is exhausted mid-run the runner records
  `model_unrecoverable` and stops honestly (partial is fine; nothing fabricated).
