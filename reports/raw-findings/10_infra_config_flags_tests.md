## 3. relay repo — dedicated findings

- **What it is**: `relay/README.md` — "Configuration management service for Razorpay." `relay/AGENTS.md`: "centralized configuration management service that stores key-value properties scoped to applications (namespaces)." Provides CRUD on Applications/Properties via 15 REST endpoints, maker-checker approval via the Razorpay Workflows service (Twirp RPC), hash-based polling for change detection, optimistic locking, and an immutable audit trail (History).
- **Modules**: `relay/service` (the server, Gin + "Foundation" framework, PostgreSQL via GORM, Redis for hash polling), `relay/client` (Go SDK consumers embed — `client.go`, `interfaces.go` define `IClient{LoadBootstrapConfigs, FetchApplication, FetchApplicationProperties, Poll}`, polling/http/trace helpers), `relay/common` (shared logger/http/errors/utils used by both).
- **Which services use it**: `relay/AGENTS.md` states consumers are "FTS, Terminals, Fulcrum." Verified by grep across the entire cloned repo set: `grep -l "razorpay/relay" */go.mod */go.sum` matches **only `fts`** among the 11 payouts-adjacent Go services in this audit's lane. `fts/internal/providers/relay/provider.go` wraps `relay/client` with `client.WithMode("poll")`, an interval from `fts/config` (`relay.poll.interval`), Basic Auth (`relay.auth.KEY/SECRET`), and a callback `config.UpdateConfigWithRelayObject` that live-patches fts's in-memory config struct from the JSON payload Relay delivers. `payouts`, `cfa`, `virtual-account`, `x-balances`, `banking-accounts`, `xperience` do **not** import relay — confirmed by absence in their `go.mod`/`go.sum` and no `relay.Client`/`relayclient` usage in their `internal`/`pkg` trees.
- **Does it deliver flags/config used by payouts at runtime?**: **No, not to the `payouts` service itself.** Relay is used by `fts` only (of the repos in this lane), gated behind fts's own feature flag `POLL_DATA_FROM_RELAY_SERVICE` (`fts/internal/config/feature_flag.go:14`, `[relay]` config toml section, `Feature.PollDataFromRelayService` boolean checked in `fts/internal/providers/relay/provider.go` `Initialize()`). This mechanism updates fts's bootstrap/runtime config (arbitrary struct-mapped key-value properties, not a payouts-specific flag), delivered over an authenticated REST poll, not to `payouts` directly.
- **Auth to Relay**: inbound REST calls to Relay Service use HTTP Basic Auth (`relay/service/config/dev.toml [auth] username="config" password="secret"`; fts side supplies `RELAY_AUTH_KEY`/`RELAY_AUTH_SECRET` env-backed credentials).
- **Ownership**: `relay/.github/repo_owners.json` — Business Unit RazorpayX, sub-group/pod "Business Banking", EM `kumar.ayush@razorpay.com` (same EM as payouts, cfa, fts, x-balances — i.e. relay sits organizationally alongside the payouts core team, even though only fts consumes it). No CODEOWNERS or servicetree.yaml/catalog-info.yaml found in relay.
